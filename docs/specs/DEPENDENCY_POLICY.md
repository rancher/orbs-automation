# Dependency Policy

**Status:** implemented. The YAML library is `go.yaml.in/yaml/v3`, moving to v4 once it is stable.

* **Standard library first.** Fewer dependencies means a smaller supply-chain surface and less to audit.
* A new dependency needs an entry here saying what the standard library would cost us. It is enforced by a `depguard` allow-list in `.golangci.yml`, so an unlisted import fails lint. Narrower rules there keep each module behind one package ([PROJECT_LAYOUT](PROJECT_LAYOUT.md)).
* Approved now:

| Module | For |
|---|---|
| `github.com/spf13/cobra` | Command tree, flags, help, completions ([CLI_FRAMEWORK](CLI_FRAMEWORK.md)) |
| `github.com/cli/go-gh/v2` | **Only `pkg/auth`**: token and host resolution, bridging off the user's `gh` setup ([GITHUB_ACCESS](GITHUB_ACCESS.md)). Doing it by hand would mean re-implementing the env var order, the `hosts.yml` reading and the keyring fallback through `gh auth token`. `pkg/api` is not approved: it brings a GraphQL library, `httpretty` and a timezone library, and is added only if GraphQL beats REST for a real need. |
| `github.com/google/go-github` | Typed REST, authenticated with its own `WithAuthToken` ([GITHUB_ACCESS](GITHUB_ACCESS.md)) |
| `github.com/go-git/go-git` | Local git operations: refs, tags, clone, commit ([GITHUB_ACCESS](GITHUB_ACCESS.md)). Preferred over shelling out to `git`: no binary needed on the machine, no subprocess inheriting environment and config, same behavior locally and in CI. Costs a larger transitive tree than `os/exec`, accepted for portability and security. |
| `github.com/mallardduck/ghreleases` | **Approved, not yet in use.** Finding a GitHub release, choosing the newest stable one, downloading its assets and verifying them against the published checksum ([CENTRAL_BUNDLE](CENTRAL_BUNDLE.md)). By hand that is release lookup, stable-versus-prerelease selection, redirects, streaming downloads and checksum parsing and comparison, which is security-relevant code we would rather not write twice. It is our own module, so we can fix it at the source. It is to stay behind the one package that downloads and verifies release assets, and the `depguard` rule that enforces that is added with the package. |
| `go.yaml.in/yaml/v3` | **In use.** The one YAML library, for the config engine (`internal/platform/config`, which also reads the user file for `internal/platform/clicfg`), the application config (`internal/config/loader`) and the versioned config API (`internal/apis`, which decodes its own documents so a version's types and their YAML form change together). Chosen because it supports strict decoding (`KnownFields(true)`, so an unknown key is a loud error) and multi-document streams (`yaml.NewDecoder`), and it was already in the tree through testify. Stay on v3 until `go.yaml.in/yaml/v4` has a stable release (it is at release candidates), then migrate. Until then it is importable only from `internal/platform/config`, `internal/config/loader`, `internal/apis` and `internal/platform/yamledit` (lint-enforced), so the migration touches known files. `internal/platform/yamledit` changes one value of a downstream file in place, which needs the node positions to splice into the original bytes, and keeps that out of the config loaders, and the loader tests pin the behavior that must not change: unknown keys, malformed input, empty files, errors naming the file. |
| `golang.org/x/net/html` | **In use, only in `internal/lifecycle`.** Reading Rancher's lifecycle dates from the SUSE lifecycle page, which is HTML. The standard library has no HTML parser, and reading a page that is built from nested tables with regular expressions would break on the first change to the markup. It is the HTML tokenizer and parser the Go project maintains, with nothing beyond the standard library and its own `atom` package behind it, and a depguard rule keeps it out of everything else. |
| `charm.land/lipgloss/v2` | **In use, only in `internal/ui/style`.** Styles for human output (color, bold, dim) and the REPL prompt, downsampled to the terminal's color profile. By hand that is a table of escape codes per profile, the downgrade from truecolor to 256 to 16 colors, and the width of text with wide characters. Measured on the real binary at about +15 modules and +1.0 MB ([CLI_OUTPUT](CLI_OUTPUT.md)). v2 `Render` always returns full escapes, so what is written is downsampled by our own `Terminal` value, never by lipgloss's own detection of stdout. |
| `github.com/ergochat/readline` | **In use, only in `internal/ui/editor`.** The REPL's line editor: history in a file, Ctrl-R, line editing and completion. By hand it is raw-mode input, redraw on wrap and resize, and history, a few thousand lines to get wrong across terminals. The maintained fork of `chzyer/readline`; 2 modules and +0.25 MB measured ([REPL](REPL.md)). |
| `golang.org/x/term` | **In use, only in `internal/cli/termfacts`.** Whether stdin and stdout are terminals, and the width of stdout. The standard library cannot say: `os.File.Stat` reports a character device, which is also true of `/dev/null`, so `gero repl </dev/null` passed for a TTY. `x/term` asks the terminal driver (`IsTerminal`, `GetSize`). It was already in `go.sum` through go-git, and it is a direct dependency now. The editor and the styling are behind their own packages ([REPL](REPL.md), [CLI_OUTPUT](CLI_OUTPUT.md)). |
| `github.com/stretchr/testify` | **Tests only, in use.** `require` and `assert` for the strong test-first workflow ([TESTING](TESTING.md)); the standard library makes table tests and diffs of structs noisy. |
| `go.uber.org/mock` | **Tests only, in use** (`mockgen` is pinned as a `tool` in `go.mod`). `mockgen`-generated mocks for interfaces at package seams (today the `Repository` of `internal/cli/branchtags`); most tests use hand-written fakes and fake transports, so tests drive behavior without network access. |

* **Developer tools that are not imported stay out of `go.mod`.** `gremlins` (mutation testing, [TESTING](TESTING.md)) is optional and installed globally by whoever wants it, because its own dependencies do not fit this policy. Tools pinned with a `tool` directive, like `mockgen`, are fine when their dependencies are acceptable.
* Test-only modules are imported from `_test.go` files and from generated mock packages, never from production code. The `depguard` `main` rule excludes `$test`, so they stay out of the production allow-list. Use them where they help, not by default: plain `testing` is fine for a simple case.
* **Integration-test dependencies live in the `test/integration` sub-module**, never in the root `go.mod` ([PROJECT_LAYOUT](PROJECT_LAYOUT.md#5-integration-tests-live-in-a-sub-module)). The same rule applies: each one gets an entry here saying what the standard library would cost us. None approved yet.
* **Running another program (`os/exec`) is an escape hatch**, allowed only for an operation go-git cannot do, or for `gero doctor` asking what the `gh` and `git` binaries would do ([GITHUB_ACCESS](GITHUB_ACCESS.md)). It is not a runtime fallback and has no obligation to mirror go-git.
  * `os/exec` is importable only from `internal/platform/execx`, the one place `gero` starts another program. Its contract (an allow list of binaries, an argument vector never a shell string, a scrubbed environment so `GH_TOKEN` does not reach a child, raw output and exit code) is in the package doc.
  * `gero repl` needs the opposite for `shell`, and for `!` if it is ever built: the user's own shell, a typed line as a string and the user's environment. That is a separate function in `execx`, `Passthrough`, which is not a method on the allow-listed `Runner`. It is used only by the REPL, takes the user's `$SHELL` and the whole environment, and has no allow list, since the user's own shell is what it runs; this is the policy entry for it ([REPL](REPL.md)).
  * `internal/platform/git/gitcli` and `internal/platform/ghcli` run their binaries through it, and each use says why. Today that is the short commit hash, whose length depends on the repository's object count and which go-git cannot reproduce ([BRANCH_TAGS](BRANCH_TAGS.md)); pushes, tag pushes, commits, worktrees, fetch, status and merge-base for `gero ship` and `gero repo tag`, which need the engineer's own SSH agent, credential helpers and signing setup ([EXECUTION_CONTEXT](EXECUTION_CONTEXT.md)); and the version and config reads for `gero doctor` ([DOCTOR](DOCTOR.md)).
* Not adopted: `viper`, logging libraries, and any library that owns the screen (Bubble Tea and its kin; `reeflective/console`). Styling is lipgloss v2 and the line editor is `ergochat/readline`, above ([CLI_FRAMEWORK](CLI_FRAMEWORK.md), [CLI_OUTPUT](CLI_OUTPUT.md)).
